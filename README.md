# 恋人空间

一个像正经 App 一样的双人情侣空间网页：手机浏览器直接打开即用，**免注册、两人实时自动同步**。

- 前端：单文件 `index.html`（内联 CSS/JS，零外部依赖，所有图标为 SVG 矢量绘制，离线也能正常显示）
- 后端：`server.js`（Node + Express，极轻量，仅负责按「空间码」中转共享数据）

## 界面结构（仿小程序/App）

- **顶部栏**：Logo + 空间名 + 分享 / 设置按钮
- **首页**：情侣头像卡（在一起天数）、快捷入口、恋爱树成长卡、最近纪念日、最新悄悄话
- **悄悄话**：聊天气泡式双人留言，可撤回自己的
- **相册**：三宫格照片墙，点击看大图，**可删除自己的照片**
- **自拍**：每日双人自拍时间轴（仿「拍给她看」），上下滑动查看，谁拍了几天一目了然，漏拍的格子会提示补拍 / 催 TA
- **我们**：恋爱资料、纪念日、心情日记、恋爱树、切换身份、分享、加密与隐私、备份、设置
- **底部 Tab 导航**：5 个页签随时切换

## 功能

- 恋爱资料：空间名、两人昵称与头像（上传自动压缩）、在一起日期
- 纪念日倒计时：还有 N 天 / 就是今天（可删除）
- 悄悄话：双人聊天气泡（可删除自己的）
- 心情打卡：6 种心情 + 一句话，时间线展示
- 恋爱树：浇水养成，6 个成长阶段（SVG 绘制），2 小时浇水冷却
- 相册：本地上传（自动压缩）或网络图片链接，大图预览，**删除自己的照片会同步到对方**
- 每日自拍时间轴：每人每天一张，左右并排 + 中间爱心，按日期倒序上下滑动；可重拍当天、可删自己的、可一键催 TA 补拍
- **端到端加密（可选）**：创建/加入空间时填入同一个「加密密码」，所有内容在上传前用 AES-GCM 加密，云端只存密文，服务器也看不到你们的悄悄话和照片；密码只有你们俩知道

## 两人如何共享（空间码 + 实时同步）

1. **一方创建空间**：打开 App 点「创建共享空间」，会生成一个 6 位**空间码**（如 `X9K2P8`）。
2. **另一方加入**：把空间码发给 TA，TA 打开 App 点「加入已有空间」输入空间码即可。
3. **实时同步**：双方各自的操作（留言、心情、浇水、上传等）会通过云端自动同步——写入即时上传，读取每 4 秒轮询一次，离线也能用、联网后自动合并，无需手动刷新。

合并规则（避免两人同时编辑冲突）：数组类数据（留言/心情/照片/纪念日/自拍）按 `id` 合并去重；**删除通过墓碑（tombstone）同步**，一方删除后对方也会消失；恋爱树成长值取较大值；标量字段（空间名/昵称等）以后修改的一方为准。

> 没有网络或后端不可用时，会自动降级为**本地模式**（数据只存在本机）。仍可随时用「分享给另一半」生成数据链接或「备份与恢复」导出 JSON 互传。

## 运行

### 方案 A：Supabase 后端（推荐，公网稳定可达，不依赖本机/沙箱）

数据走 Supabase 免费层的 Postgres + REST，**全球托管、常驻、手机公网稳定可达**，最适两个人随时手机同步。

1. 注册免费 Supabase 项目：https://supabase.com （Sign Up，免费额度足够）
2. 在 **SQL Editor** 里运行下面建表语句（建表 + 开放 anon 读写）：
   ```sql
   create table rooms (
     id text primary key,
     data jsonb,
     updated_at timestamptz default now()
   );
   alter table rooms enable row level security;
   create policy "public_all" on rooms for all to anon using (true) with check (true);
   ```
3. 在 **Project Settings → API** 复制 `Project URL` 和 `anon public key`。
4. 在 App 里「我们 → 后端配置」填入这两项并保存（两手机各填一次）。空间码机制不变。

> 也可以把这两项直接告诉我，我帮你硬编码进发布版，两人打开即用、零配置。

### 方案 B：自带 Node 后端（server.js，适合自己有服务器）

```bash
npm install
PORT=3000 node server.js
# 浏览器打开 http://localhost:3000
```

- 数据持久化在 `data/rooms.json`（每 5 秒落盘），已在 `.gitignore` 中忽略。
- 部署到服务器后，两个人打开同一个网址即可用空间码配对。

### 仅前端 / 纯静态托管（无后端，降级方案）

直接把 `index.html` 用任意静态托管（或 WorkBuddy「发布为应用」）发布；不接后端时自动走「分享链接 / 备份文件」方式互传数据（非实时）。

## 技术说明

- 单文件前端：`index.html`（HTML + 内联 CSS + 内联 JS，无构建步骤、无 CDN 依赖）
- 后端可切换：
  - Supabase（默认推荐）：`roomApi` 走 Supabase REST（`/rest/v1/rooms`），空间码即主键 id
  - 自带 Node：`server.js`（Express，`POST /api/room` 创建、`GET /api/room/:id` 读取、`PUT /api/room/:id` 写入，last-write-wins 存完整数据）
- 同步：前端 localStorage 缓存 + 4 秒轮询云端 + 冲突合并（数组按 `id` 合并去重、删除用墓碑同步、成长值取 max、标量取较新时间戳）
- 端到端加密：开启后 `WebCrypto AES-GCM` + `PBKDF2`（12 万次迭代）按空间码派生密钥，云端只存 `{enc,iv,ct}` 密文；本机 localStorage 仍为明文（设备锁负责）
